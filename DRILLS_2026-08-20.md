## Drill A — Harden the agent loop (90 min)

Folder: `02_ai_engineering/function_calling/`

This is the highest-value drill. It is already listed in your `PLAN.md` under "Hardening To Do",
and one item is an actual defect, not a nice-to-have.

1. **Fix the multi-hop bug.** Current loop executes tool calls found in the *first* response only.
   Restructure so the turn is a `while` loop: send → inspect response → if it contains function calls,
   execute all of them, send results back, inspect again → repeat until the model returns text.
2. **Add `MAX_TOOL_CALLS = 5` per user turn.** On exceeding it, return a message to the user and end
   the turn. Do not raise.
3. **Structured tool errors.** Wrap each tool invocation in `try/except`. On failure send back
   `{"ok": false, "error": "...", "tool": "..."}` as the function response so the model can recover.
   The process must not crash.
4. **Unknown tool name.** Model hallucinates a tool not in `TOOL_MAP` → return a structured error, do not `KeyError`.
5. **JSONL logging.** One line per tool call to `logs/tool_calls.jsonl`:
   `run_id`, `turn`, `tool`, `args`, `ok`, `latency_ms`. Use `uuid4` for run id, `time.perf_counter` for latency.

**Acceptance checks (run them, don't assume):**
- Ask something needing two chained tools ("weather in Mannheim, then multiply the temperature by 2") → both fire.
- Point `read_file` at a missing path → agent replies gracefully, process stays alive.
- Prompt it toward a fake tool → structured error, no crash.
- `logs/tool_calls.jsonl` has one well-formed JSON object per line.

**Also add** the `requirements.txt` and `.env.example` your `PLAN.md` promises but the folder lacks.
